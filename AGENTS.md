# subsyncd contributor guide

Before debugging, inspecting, deploying, or otherwise interacting with a production installation, read `.agents/production.local.md` completely when it exists. That ignored operator file contains host-specific access and safety boundaries; never commit it, require it in a clean clone, copy secrets from it, or guess production details when it is absent. Use `.agents/production.example.md` only as the tracked schema.

Read these documents before changing behavior:

1. `docs/implementation-status.md` for the behavior actually shipped and the resumable handoff ledger
2. `docs/providers.md` for provider, scoring, scheduling, and upgrade behavior
3. `docs/operations.md` for deployment, filesystem, LAPSE, webhook, and recovery behavior
4. `docs/references/silo.md` before changing Silo notification behavior
5. `docs/superpowers/specs/2026-09-04-standalone-github-publishing-design.md` and its matching plan before changing repository or image publication
6. `docs/superpowers/specs/2026-09-04-priority-search-dispatch-design.md` and its matching plan before changing daemon queue dispatch, priorities, leases, or webhook wakeups
7. `docs/superpowers/specs/2026-09-05-single-run-lapse-design.md` and its matching plan (the current preparation contract), plus `docs/superpowers/specs/2026-09-04-lapse-score-tier-tournament-design.md` and its matching plan before changing shortlist preparation, LAPSE evaluation, early stopping, or synchronization fallback
8. `docs/superpowers/specs/2026-09-04-structured-loki-logging-design.md` and its matching plan before changing logging levels, event ownership, fields, privacy, or Alloy/Loki guidance
9. `docs/superpowers/specs/2026-09-05-arrapi-stable-identity-reconciliation-design.md` and its matching plan before changing Sonarr/Radarr clients, catalog identities, history reconciliation, or reconciliation cursor behavior
10. `docs/superpowers/specs/2026-09-05-codebase-correctness-repairs-design.md` for the implemented repair contract, plus its matching plan, before changing exact/broad acquisition phases, archive range parsing, installation notification atomicity, deleted-sidecar recovery, YAML document validation, root Silo mappings, or provider response-lifetime permits

11. `docs/superpowers/specs/2026-09-08-full-library-discovery-design.md` and its matching plan before changing full-library enumeration, discovery completion, or snapshot concurrency fencing

`AGENTS.md` and `docs/implementation-status.md` are the authoritative entry points for current behavior. Historical design material that lived outside the original `subsyncd/` subtree is not required by the standalone repository.

Use test-driven development: add one focused failing test, confirm the expected failure, implement the smallest production change, then run the affected package with `-race`. Ordinary tests must use sanitized fixtures and local fake servers; they must never contact Arr applications or subtitle providers.

Important invariants:

- Canonical language identities are BCP 47 tags.
- Embedded subtitle inventory is cached only behind a separately persisted completed-probe fingerprint, including valid empty inventories; catalog metadata alone never establishes probe completion. Read catalog/probe/tracks from one SQLite snapshot, recheck live media after probing, and compare the original catalog identity transactionally before updating inventory. Retained deleted media cannot accept inventory or installation commits and is excluded from scan enumeration and language backfill. Migration 003 preserves legacy deletion only when every existing search is terminal/deleted and the latest retained applied lifecycle event is a delete covering the media update timestamp; ambiguous evidence stays active. Sidecars are scanned live before searches.
- Provider file hashes are calculated lazily, persisted by algorithm, and reusable only for an exact path/file-ID/size/mtime fingerprint. The OpenSubtitles hash reads only the first and last 64 KiB, uses the full 64-bit file size, and must not impose the former 9 GB dependency ceiling.
- Providers are compiled-in adapters behind the common interface. Query identity is never copied into returned candidate identity; Titlovi IMDb filters do not supply external-ID scoring evidence. Token refresh must preserve complete pagination. SubDL release ranges use the strict shared parser, absolute numbering populates absolute domain fields, and direct members require consistent season/episode evidence.
- OpenSubtitles explicitly excludes AI and machine translations on every search page. Official login routing accepts only the documented public/VIP API hosts; custom endpoints remain isolated. Signed file requests carry neither application key nor bearer token and use `download_transfer` state separately from API download quotas, retaining normal concurrency and network-failure handling.
- Provider coordination executes exactly one requested phase. Exact-hash providers run sequentially in configured order and return every genuine exact candidate; the workflow tries those candidates lazily without a cap before invoking broad search. Broad results retain configured ordering and the three-candidate shortlist. Any candidate-local rejection advances within the applicable phase, and all downloading stops after the first committed installation.
- Duplicate provider results collapse by `(provider_id, result_id)` before cache, persistence, scoring, and shortlisting. Fill absent identity fields from later duplicates, keep the first nonempty value on conflicts, union stable release evidence, and retain the strongest quality signals so provider pagination cannot consume LAPSE shortlist slots or lower a score.
- Remote provider cooldowns are persisted and release worker leases; provider code must not sleep through them. Network and HTTP 5xx failures open a provider-instance/operation circuit for 1, 5, 15, then 60 minutes and survive restart; an applicable `Retry-After` wins on non-success responses. Ignore `Retry-After` on HTTP 2xx while retaining standard rate-limit headers. Successful responses reset the transient streak only after body completion; body network failures also open the circuit, while caller cancellation, invalid content, and local writer failures do not. Non-success non-5xx responses retain status-based recovery; quota/auth state must never be erased by transient recovery. Recheck persisted availability after waiting for permits. SubDL HTTP 403 and definitive OpenSubtitles/Titlovi login HTTP 401 persistently disable their configured instance until `retry --provider` clears it.
- Provider result identities, cache records, provenance, and logs must be credential-free. SubDL discards returned query credentials and adds its configured key only to an outbound request. Cache-safe copies must deep-strip pack-member download references as well as top-level references. Migration `002_scrub_provider_credentials.sql` removes legacy contaminated provider-derived rows without resetting media, search work, or reconciliation state.
- All provider downloads are capped at 20 MiB by the workflow before reaching the common bounded extractor, even if an adapter mishandles writer errors. ZIP, RAR, and plain subtitle payloads are accepted; traversal, links, nested archives, decompression-limit violations, invalid subtitle syntax, and ambiguous season-pack members fail closed.
- A season-pack member must be uniquely identified by provider evidence, episode/range/absolute tokens, or the strict episode-title rule. Never select the first arbitrary archive member.
- Episode ranges require a complete hyphenated `SxxEyy-Ezz`, same-season `SxxEyy-SxxEzz`, or same-season `x`-form endpoint. Reversed, cross-season, ambiguous, chained, incomplete, or suffix-contaminated forms fail closed; ordinary release suffixes remain single-episode evidence. Apply forced-only member policy to every archive shape, including plain single-member movies.
- Episode archive contents override misleading provider metadata when they contain explicit conflicting episode evidence. Reject a wrong-episode singleton as candidate-local `pack_selection`, retain generic single-file compatibility for non-pack exact-episode results, continue the shortlist, and never open a provider cooldown for archive-member selection. Debug logs may include only bounded archive type/count/rule fields, never member filenames or absolute paths.
- Pack-cache directories are content-addressed and immutable. A cache hit reloads its manifest and reruns the normal strict selector for the current episode. Never persist candidate download references, follow cache symlinks, or delete paths outside the exact cache layout. Cache writes are best-effort and must not reject an otherwise valid installation.
- Sonarr episode titles are persisted because they are part of strict pack-member evidence; schema changes must update both normal and event-transaction media upserts.
- A Sonarr file associated with multiple episodes is persisted as `unsupported_multi_episode`, using the deterministically earliest episode only for display identity. Its language searches are terminal and must not enter providers, LAPSE, candidate handling, installation, or upgrades. A same-key event during an existing lease preserves that lease and coalesces one terminal rerun.
- LAPSE is the only synchronization engine. The compatibility baseline is LAPSE v2.0.5. Exact hashes bypass it; the default confidence policy also permits a non-pack first install with score >=75, identity evidence, release-group evidence, TV episode evidence, and any required movie-edition match to use the auditable `score_bypass` verdict. If Radarr identifies an edition, an edition-unknown non-hash candidate remains eligible but must use LAPSE; an explicit mismatch rejects, while an exact file hash overrides only the textual edition conflict. Uncertain candidates, packs, and upgrades require LAPSE `solid` by default. Rating/popularity points cannot replace required anchors.
- LAPSE speech-cache expiry is configured by `lapse_cache.ttl` (positive duration, default 720h), measured from last write rather than last read. Prune at mutating startup and hourly while serving, skipping active LAPSE invocations. Remove only recognized regular `.spans`/`.spans.tmp` files with rooted operations; never follow cache symlinks or traverse directories. Cleanup failures are best-effort bounded warnings; read-only diagnostics do not prune persistent cache.
- Invoke LAPSE through argument arrays with `--json --strict --no-sidecar`; standalone diagnostic analysis also uses `--dry-run` on a private copy, while acquisition prepares each required candidate once through synchronization using an explicit new `--output` plus `--no-backup`. Cancellation must kill the subprocess group.
- LAPSE JSON is an intentionally strict protocol boundary. When upgrading LAPSE, update the documented mode/reference/field allowlists and sanitized fixtures together after checking the official source contract. Classify raw diagnostics internally, but outward errors must never include stderr, JSON diagnostic values, or raw runner errors; preserve typed cancellation, verdict, and no-speech outcomes.
- The workflow persists every scored candidate without download references and caps the non-hash shortlist at three. Process it lazily by descending equal-score tiers: release score is primary, all candidates tied in the current tier are prepared with one output-producing LAPSE invocation each, viable ties rank by the resulting LAPSE confidence/provider priority/rating/stable identity, and the winner's retained output installs without another invocation. Retain prepared ties for candidate-local installation fallback and preserve original source checksums for rejections; cached pack sources remain immutable. Never download a lower tier after a higher tier installs. It installs only an exact hash, a policy-qualified `score_bypass`, or LAPSE `solid` result. `sync.policy: always` disables score bypass. Exact-hash installations are terminal; nonexact upgrades require the configured score delta (default 10).
- Deterministic `lapse_unsure`, `lapse_nothing`, invalid/oversized payload, and ambiguous pack-selection failures persist in `candidate_rejections` without time expiry and are filtered before the top-three shortlist. Rejection matching includes the exact media fingerprint, stable candidate evidence, Sonarr episode-selection metadata, optional artifact checksum, LAPSE compatibility version, and synchronization policy; never include volatile ratings/counts or download references. Cached pack rejection is member/media scoped; never delete or blacklist the whole pack/provider. `search --retry-rejected` is the explicit media/language-scoped override.
- LAPSE process/protocol, filesystem, provider, network, and cancellation failures are technical and must never poison candidate rejection state. No-speech is media-scoped and must not blacklist an individual candidate. A technical-only failed shortlist returns an error so workers advance failure backoff; deterministic-only rejection advances missing-result backoff.
- Only unchanged files owned by this service may be upgraded. A content fingerprint change invalidates old score/sync provenance; a path-only media rename rebases managed paths and retains it.
- Live inventory gates stored installation provenance. A missing managed sidecar is reacquired with first-install semantics; a present checksum-mismatched sidecar remains protected as user-owned content.
- Download/extraction/synchronization scratch uses private system-temporary workspaces (`TMPDIR`, normally `/tmp` in the container), never the media parent. Release raw and discarded candidate artifacts promptly, retain viable ties for fallback, and remove workspaces on ordinary return/cancellation. Do not sweep legacy media-root scratch directories automatically. Final installation/rollback staging stays media-local; pack publication stays cache-local.
- Every media write is root-contained, syntax-validated, staged beside its destination, fsynced, atomically renamed, checksum-recorded, and auditable. Check the current media fingerprint before publication and compare stored path/file ID/size/mtime in the installation/outbox transaction. Stale-media failures are technical and terminal. Managed replacements retain a rollback copy and restore it if the post-rename database commit fails.
- Daemon search dispatch is SQLite-authoritative and strictly orders import (300), missing/rejected (200), then upgrade (100) work before due time. It leases only immediately available workflow slots, defaults to one concurrent workflow, accepts configured values 1–8, and refills on startup, advisory webhook/reconciliation wake, completion, or recovery poll. Wakes are capacity-one and may coalesce. A same-key event during an active lease requests one immediate rerun without concurrent execution. Leases last five minutes, renew once per minute, and complete by owner compare-and-swap. Cancellation stops new leases, permits a bounded drain, then cancels active work so leases can recover.
- Search claims are filtered by current configured instance/language routes and active media inside SQLite before priority ordering and LIMIT. Disabled routes retain their rows for safe re-enable; renewals and completions remain lease-owner based. Cancellation stops new claims and dispatch, including initial startup, while already accepted work keeps its bounded drain.
- Shutdown has exactly two `worker.shutdown_timeout` windows: graceful drain, then cancellation drain. Return after the second deadline even if injected or external work ignores cancellation, and never clear abandoned durable leases. Compose must allow the full default 30+30 second budget plus exit margin (75 seconds).
- Missing/rejected results advance only the missing-attempt schedule; technical failures advance only the failure schedule; provider throttles advance neither and are scheduled at or after the provider reset. Successful/installed outcomes reset both counters.
- Filesystem publication, installation provenance, and checksum-deduplicated notification intents form one logical commit. An outbox-persistence failure rolls back the sidecar; after commit, notification delivery is asynchronous and independent, so remote failure never rolls back a valid subtitle. Workers deliver durable intents but do not create them.
- Validate the original configuration stream as exactly one non-empty YAML document before environment expansion. Empty trailing separators are allowed; any additional non-empty document is rejected without echoing or expanding its values.
- Silo integration is limited to its documented current pre-1.0 native `POST /api/v1/scan` contract, authenticated with an admin API key in `Authorization: Bearer …`. Map the media-file path into Silo's namespace, then send its parent directory so the subtree scan discovers the newly written sibling subtitle; the current production container listens on port 8080. Reject redirects and never persist or surface the API key. Silo plans to tombstone `/api/v1` at 1.0; its v2 scan method/path/schema are not yet published, so do not guess or automatically replay a mutating notification across versions. Add a separately tested versioned adapter after the official contract lands; see `docs/references/silo.md`.
- Silo path mappings accept `/` on either endpoint, choose the longest local match only at a component boundary, and scan the mapped media file's parent directory. Relative, traversal-bearing, or escaped paths fail closed before transport.
- The only HTTP routes are authenticated `POST /webhooks/{instance}`, `GET /healthz`, and `GET /readyz`. Webhook bodies are capped at 1 MiB, query tokens are compared as fixed-size SHA-256 values, response/log errors are generic, and structured logs use the path without its query string.
- Structured logs are synchronous NDJSON on stderr with `service`, `version`, `level`, `component`, and `event` as stable common fields. Once media resolves, a sanitized, single-line, bounded `media_title` follows worker/workflow/provider/LAPSE processing: `Movie (Year)` or `Show - S01E02 - Episode Title`. Keep it as a JSON field and never promote it to a Loki label. Acquisition emits one `lapse.sync_started`/completion-or-failure pair per required candidate, before tier selection and installation. Standalone diagnostic analysis retains its dry-run behavior. LAPSE invocations emit an `info` start event immediately before invocation and a matching completion or failure; start events contain no duration or result fields. Normal probes are silent; readiness logs transitions only. Candidate/release/cache detail and root-relative paths are debug-only. Never log secrets, URLs, provider bodies, absolute paths, command lines, raw LAPSE output, or promote high-cardinality IDs to Loki labels.
- Whole-movie `MovieDelete` webhooks address the stable Radarr movie ID. Whole-series `SeriesDelete` webhooks address the Sonarr series ID persisted during episode hydration by both media upsert paths. Resolve deletions and retire all matching searches with per-episode audits in one transaction, without Arr hydration or filesystem access; `deletedFiles: false` still retires catalog work. Migration 004 leaves legacy series identity unknown (zero) until ordinary hydration; never infer it from title/path/external IDs or add startup backfill. File-delete webhooks retain their file-ID semantics.
- Webhook IDs include the instance, event type, kind, file ID, size, path/previous-path, release evidence, and upgrade flag. Exact redeliveries are no-ops, but a later rename of the same Arr file ID must produce a new event ID.
- A typed `ErrOutsideScope` while hydrating an import/rename is an ignored webhook success: do not persist that item or wake work for it; continue later items in a batch, returning `ErrIgnoredEvent` only for an entirely outside-scope batch. Check retained committed event IDs before hydration so exact redeliveries do not require the old file ID to remain available. Do not generalize this to traversal, filesystem, authentication, Arr transport, or store failures. File-ID delete webhooks retain their existing behavior.
- Reconciliation uses arrapi v2.0.5 for descending 100-record paged history and current movie/episode reads, rejects incomplete/inconsistent/non-progressing pages without cursor advancement, reduces by stable Arr entity ID (`movieId`/`episodeId`), and treats the current entity as authoritative. Stable entity identity survives physical file-ID replacement; file ID remains the byte-level fingerprint/workflow identity. The detail client rejects every redirect using a cloned HTTP client policy and exposes only owned, bounded errors with cancellation/timeout classification. Root Arr mappings remain valid. The temporary hardened detail client may enrich scoring/provenance metadata but must not own history or reconciliation identity.
- Entity imports, renames, upgrades, deletes, audit rows, schedules, and the cursor commit atomically. Second-resolution history requests overlap the fractional persisted cursor, so event IDs and transactional replay must remain idempotent. Deliberately unmapped media is a safe outside-scope skip/delete; unsafe mappings or filesystem resolution fail the page closed. Reconciled same-key changes preserve lease ownership and coalesce one rerun.
- Persisted media always has a positive stable Arr entity ID; physical file ID remains separate and replaceable. Support only the current embedded lineage beginning with `001_baseline.sql`: reject applied migration names from the pre-release `001_initial.sql`–`010_media_entity_ids.sql` lineage and require an empty data directory rather than conversion or lazy adoption. Keep startup assembly and readiness offline with no Arr request or identity backfill. Background maintenance performs additive full-library discovery once per instance/type/URL/mapping/root scope, including existing instances after migration 005; explicit scan repeats it. Discovery inserts only missing entity/file identities and missing-priority language searches, preserves existing rows including deletions, leases and provenance, never infers deletions from omissions, and commits its completion marker atomically behind the instance event-revision fence. Concurrent events invalidate the snapshot; failures retry through reconciliation backoff. Failed reconciliation backs off independently per instance at 5 minutes, 15 minutes, 1 hour, then 6 hours; success restores the normal interval.
- Startup and readiness are intentionally local/offline. Startup validates configuration, existing media-root directories, SQLite migrations, LAPSE usage capabilities, and `ffprobe -version`; it never requires a live Arr/provider/Silo response. Runtime readiness rechecks SQLite and media roots only.
- Provider-instance and shared-origin concurrency permits cover the complete HTTP response-body lifetime. Release exactly once on EOF or early Close and immediately on transport/no-body failure; every adapter must close returned bodies on all paths.
- LAPSE v2.0.5 prints its usage to stderr and returns a nonzero status when invoked without arguments. It does not implement `--help`; that token is treated as an input filename. Capability detection must use an empty invocation and trust the presence of `--json`, `--strict`, `--output`, `--no-sidecar`, and `--no-cache`, while empty nonzero output or process failure is incompatible.
- The daemon owns a nonblocking advisory lock at `<data_dir>/subsyncd.lock`. `serve`, `scan`, `search`, and `retry` are mutating operations and must take it; `explain`, `doctor`, and `analyze-sync` are read-only. Acquire it before migrations/backfills or other durable initialization, retain it through application Close, and release it on failed assembly. A second mutator must fail before durable startup writes. Diagnostic assembly opens the existing current-schema database read-only, applies no migrations/backfills, creates no persistent caches, and rejects mutating methods; analyze-sync uses temporary diagnostic cache storage. A missing/outdated database requires a mutating initialization, never silent diagnostic bootstrap.
- CLI commands route through the assembled services, not HTTP management endpoints. The configuration path defaults to `/config/config.yaml`, can be set with `SUBSYNCD_CONFIG`, and every command accepts an explicit `--config`. Backend errors must pass through configuration-aware secret/media-root redaction before reaching stderr. A startup failure already emitted as a structured event must return a sanitized reported-error marker so the CLI does not print it again.
- Language routing is assembled as one workflow per canonical language, preserving that language's configured provider order. Do not use one global provider list for all worker jobs.
- Hearing-impaired/SDH tracks and candidates are disallowed by default. Only an explicit `allow_hearing_impaired: true` makes them satisfy inventory or remain eligible during candidate scoring.
- The production image is multi-stage, fixed to Go 1.27.1, Debian 13.2, and checksummed LAPSE v2.0.5 amd64/arm64 release archives. Debian 12 is incompatible with the upstream LAPSE binary's glibc requirement. It defaults to UID/GID 1000; Compose may override the rootless runtime identity through host-side `PUID`/`PGID` interpolation and must apply the same IDs to `/tmp` tmpfs. Do not add a root entrypoint or automatic ownership changes. The root filesystem is read-only; configuration is read-only and only data, temporary, and media mounts are writable.
- Container builds must work with BuildKit target arguments and legacy native Docker. When `TARGETARCH` is absent, derive the native architecture inside each build stage; never silently combine an amd64 LAPSE binary with an arm64 runtime or vice versa. Keep the legacy-compatible root `Dockerfile` and BuildKit-only `Dockerfile.release` runtime stages synchronized; only the release variant may mount and link the OpenSubtitles application-key secret.
- Tagged `test/e2e` tests own the black-box embedded skip, exact-hash bypass, broad/LAPSE/install/Silo, and restart-dedup paths. Real provider contracts stay behind `provider_contract` and must skip without credentials.
- Installation rollback errors are joined with the initiating failure. Never hide a failed removal, restoration, or directory sync, and never delete the retained rollback copy after failed restoration. An incompletely rolled-back sidecar is protected untracked inventory that requires operator inspection.

Local verification uses writable caches:

```bash
GOCACHE=/tmp/subsyncd-gocache GOMODCACHE=/tmp/subsyncd-gomodcache go test ./... -race
GOCACHE=/tmp/subsyncd-gocache GOMODCACHE=/tmp/subsyncd-gomodcache go vet ./...
```

Update `docs/implementation-status.md` at every completed task boundary with the commit, adopted/tightened/rejected behavior, tests run, and next task.
