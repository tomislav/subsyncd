# Logging internals

Developer reference for event fields, levels, and privacy guarantees. For everyday use, see the [logging guide](../logging.md).

## Output and event contract

`subsyncd` writes one JSON event per line to stderr. View recent logs or follow new events with Docker Compose:

```bash
docker compose logs --tail=100 subsyncd
docker compose logs -f subsyncd
```

Configure the minimum level in YAML, or override it through the environment:

```yaml
logging:
  level: info
```

```dotenv
SUBSYNCD_LOG_LEVEL=debug
```

Valid levels are `debug`, `info`, `warn`, and `error`; omitted configuration defaults to `info`. The environment value takes precedence. Values are read only at startup, so a change requires a service restart. Use `info` continuously. Enable `debug` only for a bounded diagnostic run, then remove the override and restart at `info`.

Every record has `time`, `service`, `version`, `level`, `component`, `event`, and `msg`. Operational records add typed fields such as `job_id`, `media_id`, `media_title`, `media_kind`, `file_id`, `language`, `provider`, `candidate_id`, `outcome`, `reason`, `attempt`, `duration_ms`, `retry_at`, or `next_upgrade_at`. Once media is resolved, `media_title` follows the processing context through worker, workflow, provider, candidate, LAPSE, and completion events. Movies use `Movie (Year)` and episodes use `Show - S01E02 - Episode Title`; the value is normalized to one line and bounded to 2,048 Unicode code points. Follow one operation by parsing JSON and filtering on `job_id`.

The level behavior is:

| Level | Intended records |
| --- | --- |
| `info` | Service, webhook, durable job, search, archive-member selection, candidate rejection/retained skip, selected candidate, install/provenance, notification, reconciliation, and recovery lifecycle summaries. |
| `warn` | Expected degraded states such as throttling, persisted provider cooldown/circuit/auth transitions, non-solid LAPSE decisions, readiness loss, and bounded shutdown drain timeout. |
| `error` | Technical failures that require retry or operator attention. |
| `debug` | Candidate score components, release-name diagnostics, cache decisions, tournament/fallback decisions, and media paths only when safely root-relative. |

Successful `/healthz` and `/readyz` requests are intentionally silent. Readiness emits only a transition to unhealthy and a later recovery, avoiding probe noise. Webhook paths exclude query strings. Error text passes through configuration-aware redaction and is normalized to one line. Filesystem errors carry only their cause, never the path the operating system attaches, because redaction replaces configured roots but not the media path beneath them. Credentials, bearer/API keys, provider URLs and bodies, notification payloads, absolute media/data/temp paths, command arguments, and raw LAPSE stdout/stderr are never intentional log fields. The one deliberate exception for provider text is `provider.response_unrecognized` (warn, `component=provider`, with `provider` and `operation`): when SubDL answers with an unrecognised status-false message, its optional `excerpt` field carries at most 80 runes of that message, reduced to letters, digits and `.,:;'!?()-_%`, single-line, with the configured API key and credential-looking tokens replaced by `[redacted]` and a cut marked with `…`. Event fields bypass error redaction, so the SubDL client redacts the excerpt itself, and the text never enters an error message, whose wording `workflowErrorKind` uses to classify failures. If root containment cannot be proven, even the debug relative path is omitted.

A manual search (`search`, in-process or in the daemon) logs `job.started` and `job.completed` itself (`component=app`, `priority=manual`, a `manual-<hex>` `job_id`, plus `media_id`, `language`, `instance`, `media_kind`, `file_id` and `media_title`); `job.completed` carries `outcome` (the workflow outcome, `failed` at error level with `error_kind=manual_search`, or `canceled`) and `duration_ms`. A manual run past its time limit logs `job.timed_out` (warn, `component=app`, `priority=manual`) before its failed `job.completed`. The workflow events between them carry the same context. When diagnosing one workflow, follow records with the same `job_id` and inspect `job.started`, provider search/download events, `candidate.selected`, any LAPSE phase, installation/notification, and `job.completed`. Acquisition LAPSE work emits one `lapse.sync_started` at `info` immediately before the subprocess call, followed by the matching completion or `lapse.failed` event. Selection and installation follow preparation of the complete current score tier; a sync completion alone does not mean that candidate was installed. Start events contain correlation, phase, provider, candidate, and compatibility-version fields, but no duration or result fields. Completion and verdict-rejection `lapse.failed` events carry LAPSE's reported `verdict`, `mode`, `reference` (`embedded`, `vad`, ...), `offset_ms`, `ratio`, `confidence`, `sigma`, `margin`, `agreement`, `coverage`, `parts` and `splits`, so a large offset on a `nothing` verdict is visible. `sigma` is the scale LAPSE's own bar for `solid` uses (`--confidence`, default 8), so a rejection just under that bar shows as a sigma just below 8. Technical LAPSE failures leave those fields zero. Candidate details require a temporary `SUBSYNCD_LOG_LEVEL=debug` restart; return to `info` immediately afterward.


Webhook processing is asynchronous. The HTTP handler logs `webhook.accepted` and then `webhook.queued` (info, `component=http`, `instance`, `event_count`, `status` 202) once the body is stored, or `webhook.applied` with `outcome=ignored` and `status` 204 for an event type it does not use, or `webhook.rejected` (warn) with `status` 400 for a malformed one. The inbox processor then logs `webhook.applied` (info) with `outcome` `applied`, `duplicate` or `ignored`, `event_count`, `applied_count`, `attempt` and `duration_ms`; a failure logs `webhook.failed` with `outcome=retry_scheduled` (warn, with `retry_at`) or, after the sixth attempt or for an invalid stored payload, `outcome=abandoned` (error); an inbox that cannot be read or written logs `webhook.failed` with `outcome=inbox_unavailable` (error, with `retry_at`: the processor waits 5 seconds, doubling up to 5 minutes, until a pass succeeds). These records carry `error_kind=webhook_processing` or `webhook_inbox` with the redacted message. `search.resume_reset` (warn, `component=store`, `media_id`, `language`) reports saved provider progress that failed validation when its search was leased; the search runs the full route and the progress is cleared. The list itself is never logged. `queue.media_file_unavailable` (info, `component=worker`) reports a search whose media file is missing (not-found class) while the storage holding it still lists files, so the media breaker did not count it; hangs and read errors always count. `install.recovered` (info, `component=workflow`, `media_id`, `language`, `outcome` `recorded`, `undone` or `cleaned`) reports an install a crash interrupted between publication and recording, settled at startup; `install.recovery_failed` (warn) one that could not be settled, retried at the next start, and `install.recovery_incomplete` (warn, `component=app`) summarizes that startup left some unsettled. `install.recovery_timed_out` (warn, `component=app`, `timeout_ms`) reports a startup sweep abandoned after 30 seconds (a hung mount); startup continues and the rows are retried at the next start. `scan.completed` (info, `component=app`, `instance`, `media`, `deferred`, `probe_skipped`, `force_probe`, `duration_ms`) ends every scan the daemon ran, including one that outlived its request's wait; `scan.failed` (warn with `outcome=failed` and `error_kind=scan` plus the redacted error, or info with `outcome=canceled` when shutdown canceled it) reports one that did not finish. `history.record_failed` (warn, `component=app`, `error_kind=search_history`) reports a manual search whose history row could not be written after the search finished; `history.prune_failed` (warn, same fields) reports a failed hourly prune of history older than 30 days, retried the next hour. `webhook.inbox_orphaned` (warn, `component=app`, `instance`, `webhook_count`) reports, at startup, webhooks stored for an instance no longer configured; `forget-instance --yes` deletes them. `provider.cooldown_save_failed` (warn, `component=provider`, `provider`, `scope`, `reason`, `error_kind=provider_state`) reports a cooldown that could not be saved while the response that called for it was still used (an OpenSubtitles link that used up the quota). `install.pending_clear_failed` (warn) reports a pending-install record that could not be cleared after its install settled; the next startup clears it. `install.rollback_cleanup_failed` (warn, `component=workflow`, `error_kind=rollback_cleanup`) reports a replaced subtitle's rollback copy that could not be deleted (or forgotten) after its install was recorded; the install stands and the startup sweep retries. That sweep logs `install.rollback_sweep_completed` (info, `component=app`, `removed_count`, `skipped_count`) when it found any recorded copy, `install.rollback_sweep_failed` (warn, `error_kind=rollback_cleanup`) when it stopped on an error, and `install.rollback_sweep_timed_out` (warn, `timeout_ms`) when it was abandoned after 30 seconds; none carries a path.

`install.removed` (info, `component=workflow`) is logged by `Installer.RemoveManaged` after the transaction that deleted the installation record, wrote the `removed` history row and queued the notification intents commits, and before the hidden set-aside file and the old rollback copy are deleted. Fields: `provider`, `candidate_id` (sanitized), `checksum_prefix` (12 characters of the removed subtitle's checksum), `rollback_deleted`, and `reason` when a media change rather than a reject removed it (`media_replaced`, `media_renamed`; see `Installer.ReconcileInstallation`); correlation fields come from the job context. It never carries the subtitle path. `install.record_dropped` (info, `component=workflow`) is logged by `ReconcileInstallation` after it deleted a stale installation record without touching the sidecar, with `reason` (`sidecar_missing`, `sidecar_changed`, `media_replaced`), `provider`, `candidate_id`, `checksum_prefix` and `rollback_deleted`; `install.renamed` (info, `component=workflow`) after an installation followed a rename of its media file, with `moved` (subsyncd moved the sidecar to the new name, rather than finding Arr had), `provider`, `candidate_id` and `checksum_prefix`. Neither carries a path. `reject` logs `candidate.rejected` (info, `component=app`) when its rejection commits, with `provider`, `candidate_id`, `reason_code` (`user_<reason>`), `media_id` and `language`. A removed search completes with `outcome=removed` and `reason=rejected_subtitle_removed` in `search.completed` and `job.completed`.

`instance.forgotten` (info, `component=app`) is logged once by `forget-instance --yes` after its transaction commits, with `instance` and `media_count`, `search_count`, `installation_count`, `rollback_copy_count`, `candidate_count`, `rejection_count`, `notification_count`, `event_count`, `replay_count`, and `history_count`; a preview logs nothing. `webhook.connection_created` and `webhook.connection_adopted` (info, `component=catalog`, `instance`, `connection_id`), `webhook.connection_repaired` (info, plus `changed`, a comma-joined subset of `url,method,events`: key groups, never values), `webhook.connection_ok` (debug, `connection_id`), `webhook.connection_foreign` (info, `count`), `webhook.connection_ambiguous` (warn, `count`) and `webhook.connection_sync_failed` (warn, `reason`, `status`; with `reason=internal` also `error_kind=webhook_connection_sync` and `error`, passed through the emitter's redactor) report the managed Arr webhook connection. `reason` is one of `arr_unreachable`, `arr_status`, `arr_response_invalid`, `arr_test_rejected`, `arr_test_unreachable`, `name_unavailable`, `schema_missing_webhook` or `internal` (any error that is not a classified sync failure); `status` is Arr's HTTP status or 0. Webhook URLs, tokens, Arr response bodies and the fields of any connection other than the owned one's numeric ID are never logged, wrapped into errors or persisted. `control.request_completed` (info, `component=control`) and `control.request_failed` (warn) report each command the CLI hands to the running daemon over the control socket: `command` (a known command name, or `unknown`), and for success `outcome` and `duration_ms` (plus `media_title` when a request resolves one media file, for commands that do); for failure the error `code` and a redacted `error` with `error_kind=control`. Arguments, socket paths and raw client input are never logged. `webhook.token_rotated` (info, `component=app`, `instance`) is logged by `rotate-webhook-token` and never carries either token. Go's HTTP server reports its own failures as `http.server_error` (`component=http`) with `reason` `panic` (error level), `accept`, `tls_handshake`, or `other` (warn), plus `error_kind=http_server` and the redacted first line of the server message; panic stack traces are never logged. The worker logs route pauses once per transition: `queue.route_paused` at warn with `language`, `media_kind`, `provider_count`, and either `reset_at` or `reason=disabled`; `queue.route_resumed` at info with `language` and `media_kind`. A paused route is logged again when its reset time changes, including when only disabled providers keep it paused. A failed availability check logs `queue.route_check_failed` at error with `error_kind=route_check`, and that dispatch leases nothing; cancellation during shutdown is not logged. A pause that applies only to multi-episode files (single-episode-only providers can still serve the route) adds `episode_ranges_only=true`. These events carry no provider IDs. `reconcile.deferred` (warn, `component=worker`) reports a committed reconciliation page that is waiting for unreadable current media, with `instance`, `deferred_count`, `deferred_media` (at most ten log-safe `Sonarr episode <id> (<media title>)`, `Sonarr file <id> (<series> - season <n>)` or `Radarr movie <id> (<media title>)` labels, never paths; empty when a catalog reports the bare sentinel), `retry_at`, and `duration_ms`; it does not increment the failure backoff that `reconcile.failed` (error) reports. `reconcile.snapshot_deletions_withheld` (warn, `component=catalog`) reports a catalog identity snapshot that would retire all tracked identities, or more than half and at least 10, with `instance`, `media_kind`, `active_count`, `missing_count`, and `snapshot_count`; history from the page still commits. `reconcile.multi_episode_recheck_failed` (warn, `component=catalog`) reports a legacy multi-episode file that could not be re-read from Sonarr, with `instance`, `file_id` when known, and `error_kind`.

`archive.members_selected` is an info event with provider, candidate_id, selection_rule, matching_member_count and subtitle_member_count. Deterministic content/preparation failures emit `candidate.rejected` immediately at info with a bounded reason_code; selection failures add bounded archive type/rule/counts. `candidate.skipped` reports retained rejections at info. Multi-version preparation and selected/installed records carry member_index/member_count so repeated LAPSE events for the same provider candidate can be distinguished. Indices are local to the current preparation group; no filename or path is emitted. `candidate.rejection_details` and score/cache/tournament details remain debug-only.
