User authorized both identified pack-selection repairs and info-level logging improvements on 2026-09-08. This extends the single-run LAPSE preparation contract.

Accept an optional dot between season and episode (`S04.E13`) in the shared token and range parser. Preserve complete-token boundaries, same-season explicit ranges, contradictory-coordinate vetoes, and malformed-range rejection.

Keep `pack.Select` strict. Acquisition and cache lookup may obtain at most three distinct-content versions when the strict selector reports multiple explicit target-episode token matches. Each version must independently pass all normal selection guards. Provider-direct ambiguity, title-only ambiguity, range ambiguity, unknown episodes, forced-only members and ambiguous exact-hash results remain fail-closed. Identical checksums collapse before the version bound. More than three distinct versions reject the result rather than choosing an arbitrary subset.

Download a provider result once. Keep each selected version as a private source, run required LAPSE once per version, and retain its validated output. Versions inherit their provider result's release score, do not consume additional provider shortlist slots, and participate in the existing equal-score confidence tournament. Installation fallback reuses prepared outputs. Maximum work is three provider results with up to three versions each; lower score tiers remain lazy. Exact hashes keep strict single-member selection and bypass.

Preserve provider/result identities. Version rejection signatures add the original selected-content checksum, separate from the provider-wide signature and synchronized output. A rejected version never hides a sibling. Aggregate provider/media/language rejection only when every version failed deterministically; a technical or media no-speech failure prevents aggregation. Cached manifests and sources remain immutable, reselect on lookup, verify all selected checksums, and filter each rejected version before touching access time. A later episode is independent.
